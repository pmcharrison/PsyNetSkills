# Experiment audits

Portable experiment readiness audits are owned by **PsyNet**, not this workshop
repo. For a standalone experiment, run from the experiment directory so the
audit lives at `./audit/`:

```bash
psynet audit init
psynet audit validate
psynet audit mark-present <artifact_id>
psynet audit render
```

Use the Click command only (`psynet audit …`). There is no separate
`psynet-audit` console script.

`experiment.source_path` defaults to `.` (the experiment directory that contains
`audit/`). Validate checks structure and can pass while blockers remain; that
means the packet is coherent, not that the experiment is ready. Render runs
validate first (use `--allow-invalid` only to preview a broken manifest).

Monitor snapshot publishing copies `/static/...` assets from the **installed
Dallinger** frontend (not a vendored copy in PsyNet).

Install PsyNet with the optional extra (already pulled in by `psynetsk-tools`
via `psynet[audit]`):

```bash
# In ~/PsyNet
uv pip install -e '.[audit]'
```

## Contract

An audit is a portable packet with:

```text
audit.json
PROMPT.md          # optional
PLAN.md            # required for profile psynet.core
TIMELINE.md
REPORT.md
artifacts/
analyses/
logs/
site/              # generated by render; usually not committed
```

`audit.json` is the machine-readable manifest. It may declare:

```json
{
  "profile": "psynet.core",
  "extensions": []
}
```

Schema, CSS, and Python helpers live in PsyNet under `psynet.audit` and
`psynet/resources/audit/`. See PsyNet docs: *Experiment development → Experiment
audits*.

## Challenge extension (`psynetskills.challenge`)

Challenge attempts in PsyNetSkills use the **attempt root as the audit packet**
(not a nested `audit/` folder). New attempts declare:

```json
{
  "profile": "psynet.core",
  "extensions": ["psynetskills.challenge"]
}
```

The extension adds workshop sections that still use **core** kinds
(`markdown`, `files`, `json`, `evidence`, …), with stable ids such as:

| Section id | Kind | Typical path |
|------------|------|--------------|
| `challenge` | markdown | `challenge/INSTRUCTIONS.md` |
| `plan` | markdown | `PLAN.md` |
| `evaluation` | markdown | `EVALUATION.md` |
| `learnings` | markdown | `LEARNINGS.md` |
| `timeline` | timeline | `TIMELINE.md` |
| `evidence` | evidence | (classified from `artifacts/` + `analyses/`) |
| `code_files` | files | `code/` |
| `evidence_files` | files | evidence listing |
| `agent_metadata` | json | `agent.json` |
| `challenge_snapshot` | files | `challenge/` |

Target layout:

```text
challenges/<slug>/attempts/<name>/
  audit.json
  PLAN.md
  REPORT.md
  TIMELINE.md
  EVALUATION.md
  LEARNINGS.md
  agent.json
  artifacts/          # was evidence/
  analyses/
  logs/
  code/
  challenge/
  site/               # optional local render
```

Initialize with the attempt-challenge skill (or
`psynetsk_tools.challenge_audit.init_challenge_attempt_audit`). Validate from
the attempt root:

```bash
cd challenges/<slug>/attempts/<name>
psynet audit validate
psynet audit render
```

Skills-side checks (`psynetsk-validate`) require the challenge extension section
ids and warn when an in-progress attempt still lacks `audit.json`.

## Dashboard dual-read

The dashboard exporter:

1. If `audit.json` exists → load section order from the manifest and overlay
   workshop polish (criteria disclosure, learning-action checkboxes).
2. Else → legacy synthesis from `evidence/` (historic attempts).

Do **not** bulk-rewrite the archive. Optional hand migration:

```bash
uv run psynetsk-migrate-attempt-audit challenges/<slug>/attempts/<name>
```

Artifact URL prefixes: prefer `PSYNET_AUDIT_ARTIFACT_URL_PREFIX`; the legacy
`PSYNETSK_ARTIFACT_URL_PREFIX` remains a fallback for dashboard preview CI.

Agent workflow for standalone experiments: skill `produce-experiment-audit`.
Agent workflow for challenges: skill `attempt-challenge` (audit-root layout).
